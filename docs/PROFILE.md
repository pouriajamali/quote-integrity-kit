# Synthetic European call profile v1

Audience: a quant or data engineer inspecting a small offline options snapshot
before analysis. The first scenario uses one explicitly fictional contract and
one expiry. It makes no assertion about a real exchange's conventions.

The normative constants are in `profiles/synthetic-european-call-v1.json`.
The option is a European cash-settled call on the fictional SYNTH underlying,
strike USD100, multiplier100, expiry 2026-11-30T16:00:00Z. Premiums are USD per
underlying unit. The contract premium in cents is the quoted cents times100,
checked for signed Int64 overflow. No currency conversion, margin, holidays,
delivery, exercise, model calibration or real venue calendar is inferred.

`bid` and `ask` are displayed price observations. They do not promise a fill or
depth. `mark` is an optional informational number; it never substitutes for a
missing bid/ask or enters freshness/coverage evidence. A computed midpoint is
only an arithmetic midpoint: odd bid+ask cents produce half a cent, reported
exactly using decimal arithmetic. Zero is a valid literal price; absent/null is
unknown and never silently becomes zero. Negative option premium is refused.

Timestamp strings are exactly UTC seconds, `yyyy-MM-ddTHH:mm:ssZ`, with valid
calendar dates. Event time must not exceed observed time; observed time must
not exceed the declared historical `asOf`. Event and asOf must be strictly before
expiry. Age is asOf minus event time; age equal to the threshold passes. This is
declared-context freshness, not source clock authentication. No known-at or
publication time is manufactured. `observedAt` means only the caller's assertion
of observation time, not verified receipt or effective time.

Each JSON record retains its native bytes indirectly through the exact input
SHA256 and row ordinal. Its id is a unique caller label, not an execution or
market identifier. Unknown fields are quarantined instead of ignored. A bad
schema, malformed JSON, duplicate JSON property, invalid UTF8 or resource cap
violation makes the whole input incomplete; it does not yield an admissible
prefix. Duplicate row ids or unexpected/missing declared ids fail coverage.

## Input envelope

UTF8 JSON object, no BOM, comments or trailing commas; at most1MiB, depth8,
1..1000 rows,1..1000 expected ids, and ids1..64 ASCII letters/digits/underscore/
hyphen starting with a letter or digit. Every object has exact fields.

- `schema`: `quote-integrity-v1` (decimal prices) or
  `quote-integrity-scaled-v1` (integer price strings; optional second adapter).
- `profile`: `synthetic-european-call-v1`.
- `sourceKind`: `ORIGINAL_SYNTHETIC` or `USER_SUPPLIED_UNVERIFIED`.
- `dataUse`: `allow`, `deny` or `unknown`. This is an unauthenticated declaration,
  separate from software licensing. Allow never proves legal rights.
- `asOf`: a declared historical UTC instant, not the current system time.
- `maxAgeSeconds`: integer0..604800.
- `expectedIds`: unique explicit labels. This is only declared-set coverage,
  never market completeness.
- `quotes`: rows with exact fields `id`, `instrument`, `venue`, `currency`,
  `eventTime`, `observedAt`, `bid`, `ask`, `mark`. Each price is a string or null.
  The scaled adapter uses `bidUnits`, `askUnits`, `markUnits` instead.

Decimal syntax: `-?[0-9]+(\.[0-9]{1,2})?`, at most32 characters. No exponent,
whitespace, plus sign, comma, rounding or locale inference. Prices must map
exactly to Int64 cents, and premium times multiplier must fit Int64 cents.
Scaled syntax: `-?[0-9]+` at most32 characters, same numeric range and checks.
The adapter name carries the unit; a numeric JSON token is not a string.

Row results: `ACCEPT` only if all mechanical checks pass; every bad/unknown row
is `QUARANTINE`, with stable sorted reason codes. Whole-dataset decision is
`REJECT` for mechanical failure or denied use, `HOLD` when use is unknown,
otherwise `ADMIT_PROFILE`. RowQuality, coverage, freshness and useDeclaration
remain separate axes. `ADMIT_PROFILE` is permission under this limited caller
policy, not proof of market data authenticity, legal rights, future execution,
numerical model validity, profitability or fitness for every analysis.

## Independent expected values and tolerances

Fixture expected results are literal decisions/reasons, reviewed from the
contract, not generated by the product. Decimal scaling and checked arithmetic
use zero tolerance. A separate Python Decimal reference exercises exact unit
values and midpoints without calling the C# implementation. No pricing/model
tolerance or arbitrage constraint is imposed outside a declared model.

All public fixtures are newly invented for this project, under MIT. They contain
no downloaded market data, account records or employer implementation. User
input rights remain the user's declaration. Real data support requires a
separate profile and explicit data-use review.
